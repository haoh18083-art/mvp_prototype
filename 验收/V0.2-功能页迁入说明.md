## 跟进工作台与客户空间的关系（2026-09-20 修正）

此前 `followup-workbench` 既占据销售的一级菜单位，又实际承载客户空间详情，把两件事混成了一个页面。本轮拆开：

- **跟进工作台**是销售侧处理各类信息的独立工作台，本版尚未实现。销售菜单保留该条目但**封存**：渲染为不可点击的 `<span>`，带 `aria-disabled="true"` 和「本版未开放」标记，不进入 Tab 焦点顺序，角色切换也不会落到它。
- **`followup-workbench` 路径不禁止访问**，直接输入 URL 仍可打开，并按**次级页面**渲染：页面标题为「客户空间」，操作条显示「返回客户空间列表」，左侧高亮父级「客户跟进空间」而不是自身。带 `solution` 参数进入时返回目标仍是该客户空间的方案页签。
- 销售登录后的落地页由「跟进工作台」改为「客户跟进空间」；进入具体客户仍从列表点击，链接不变。

真正的跟进工作台实现后，解除该菜单位封存即可，客户空间路径与其父子关系不受影响。

## 登录与角色入口

- 根入口 `index.html` 为 V0.2 登录页；17 个功能页的逐页评审入口迁至 `prototype.html`。
- 登录页提供超级管理员、销售运营、销售和解决方案人员四个演示身份，选择后自动填入本地凭据。
- 登录成功后分别进入「运营配置」、「经营洞察」、「客户跟进空间」和「方案人员工作台」，并带上与身份匹配的 `role` 和 `as` 参数。
- 会话只保存最小演示身份，不保存密码；退出登录会清理会话并返回根登录页。
- 该链路是静态原型交互，不是真实身份鉴权。为便于需求评审，带角色参数的功能页直达链接仍然可用。

## 数据及权限

- 使用独立本地存储，不依赖旧批次的审批与组织数据。
- 销售仅见本人空间；解决方案人员仅见显式承接池；运营 / 超管可全量查看空间。
- 冻结空间保留只读；客户级确权样例可进入但商机为空。
- 客户池和销售的归属变化来自 CRM；新功能页没有本地创建归属池或更换空间归属的入口。
- 承接池调整支持逐项多选，不提供“全部”选项。提交时重读范围，已打开页面不能继续对失去权限的方案操作。
- 多空间推送为每个空间创建独立记录，正文、附件、外部链接、已读时间与回复时间互不串联。销售打开详情后已读，一次回复闭环；方案人员打开后标记回复已读。
- 只有原推送人能撤回未读方案。撤回后销售侧记录与提醒失效。
- 撤回记录不从方案人员的反馈看板消失，并在详情中保留撤回时间与事件记录；承接池变化导致的旧空间非撤回方案仍按当前可见范围隐藏。
- 催办演示采用 24 小时间隔，只生成本地提醒；看板记录催办次数和最近时间，不是生产限流口径的定版。
- 录音挂载与跟进记录原子写入，重复挂载被阻止。

## R03–R06 闭环补全（2026-09-20）

客户空间改为 R04 定义的五个入口：**概览、客户、商机、跟进、资料**；原「跟进记录、方案往来、录音、客户画像」下沉为「跟进」入口内的子页签。旧链接 `tab=followups|solutions|recordings|profile` 保留为别名，仍落到跟进下对应子页签。

- **R03 空间内容装载**：资料入口展示「内容范围」六层（客户级信息、已确权商机、跟进与活动、录音关联、方案往来、外部资料）各自的装载状态与数量，单层失败不掩盖其余层。方案人员在承接池内的正常空间可上传 `.md`：逐份校验格式、正文与大小，不合格文件不提交；内容完全相同的文件不重复挂载，同名不同内容作为新增资料且不覆盖旧资料；挂载失败保留原文并支持单份重试，同批已成功结果不回滚。冻结空间与承接范围外不提供上传和重试入口。
- **R04 客户空间全景与溯源**：概览为默认入口，含十个板块、更新时间与当前版本；每条结论给出可点击的依据入口，失效来源保留标识与不可用说明且不可点击，无依据的板块不输出结论。提交跟进或挂载资料后生成「本次变化」，区分新增、更新前后对比、待确认、信息冲突、无变化、处理中和更新失败七种口径，有变化时给直达入口。概览内提供快捷问答，只读取本空间有权上下文；无依据时明确说明不作答，冻结空间不开放新问答但历史可读。
- **R05 角色可见边界与承接池**：客户空间列表新增「当前权限结果」区域，展示身份、角色、可读范围、可写范围与本次判定结果；账号停用时展示拒绝结果与重新进入入口，且不暴露空间是否存在。客户入口新增「同客户在跟名单」，只给销售与确权类型，不返回其商机内容。承接池配置新增当前生效范围、最后更新时间和「新增 / 移除 · 下一次读取生效」变更提示。
- **R06 客户归属分布视图**：新增 `pages/customer-ownership.html`（超管 / 销售运营可见）。按客户列出当前归属销售、确权类型、空间状态与异常数，详情区将「当前归属」与「历史归属」左右分栏；历史按时间展示进入、移除、恢复、空间冻结及事实类型，只读且不提供任何写入或恢复操作。待对应人员不计为有效归属销售，未分配商机不建立销售空间，内容失败的空间不显示为正常可用，三类异常均提供到运营配置对应分面的详情入口。

待明确事项在原型中按以下假设演示并已在界面标注：外部资料单文件上限 20 MB；挂载失败重试开放给上传者本人与超管；`.md` 为唯一允许格式。

## R07–R08 方案协同闭环补全（2026-09-20）

- **R07 方案人员工作台**：新增独立的方案人员工作台，以承接客户为主线去重展示；展开客户后查看其销售空间、周期内更新、跟进数量和方案阅读指标。空间全景抽屉区分正常 / 冻结状态，正常空间提供补充外部资料入口，冻结空间只读；工作台通过次级导航进入方案推送和反馈看板。
- **R08 方案定向推送**：新增方案推送次级页，推送表单支持正文、单个演示附件和外部链接。每个空间重新校验承接范围和生命周期，单个空间失败不回滚其他成功结果；附件仅保存文件名与大小，不上传真实文件。
- **R08 反馈看板**：新增反馈看板次级页，按方案 / 客户空间展示接收销售、推送与阅读时间、反馈状态、未读天数、催办记录和详情入口；提供全部、未读、已读待回复、已回复、已撤回筛选。撤回后保留发起方审计记录，并禁止销售侧继续查看原文。
- **兼容策略**：保留 `solution-center.html` 旧路径和原有菜单入口，新评审主路径改为 `solution-workbench.html` → `solution-push.html` / `solution-feedback.html`；旧路径不作为 R07/R08 的主入口。

## R12 消息触达闭环补全（2026-09-20）

- **统一提醒入口**：方案推送 / 回复 / 催办、客户信息更新、归属变化、空间冻结与解冻、CRM 异常与待对应都经统一入口生成提醒；每条提醒有明确接收人、产生时间、来源、直达目标和去重键，同一事项重复触发只合并计数，不重复打扰。
- **收件箱**：按接收人隔离（方案回复只发给方案作者），未读优先并按时间排序；条目展示产生时间与来源空间；点击按当前权限直达来源空间、本次变化详情或运营视图，来源无权时保留历史提醒但不给内容入口。
- **推送与投递结果**：站内必达、移动端推送尽力；每次提醒只推一次，失败（失败 / 未安装 / 超时）在站内标注「未送达」且不自动补发。超管在「运营配置 → 消息触达 → 投递结果」按接收人、状态和时间查询，该分面仅超管可见。
- **运营侧提醒**：CRM 对齐异常、人员待对应、空间内容更新失败只生成销售运营与超管的站内提醒，不打扰销售；消息中心对超管与销售运营开放。
- **等待规则**：归属新增与解冻提醒在空间内容就绪前保持「等待空间就绪」，不进入收件箱也不发起推送；内容重试就绪后自动释放并补一次推送。
- **口径修正**：按 M06 定版移除「飞书触达」页签及其启停、绑定治理演示；本版只有站内与移动端推送两条触达路径，不做渠道偏好。

## R13–R17 闭环补全（2026-09-21）

- **R13 今日该跟与优先级排序**：新增 `pages/today-follow.html`（销售）与 `pages/insight-ops.html`（运营 / 超管）。每日快照按「未冻结且至少一条商机确权」的空间产出，锁定产出日期、输入截止、策略版本与名单结果，当天重复打开只读不重算；名单最多 5 条并保留截断说明，每条含状态种类、一句话说明、下一步与原文级依据（标注来自状态 / 排序 / 动作哪一步判断，不出现提示词名）。已生成且 ≥1 条时经 R12 提醒销售，整批失败只提醒运营；尚未生成 / 没有足够依据 / 生成失败 / 尚无可判断空间四种分支各自成立，均不沿用昨日。星标与暂不跟进（原因必填、结束日选填、过期自动失效）只写入次日输入，当天名单不变；客户空间内同样提供标记入口。运营侧三份提示词独立编辑、保存草稿、按空间试跑对照（冻结样本标注），上线与回退均下一自然日生效；产出时点支持全员默认与按销售覆盖（覆盖值等于默认视为取消）。

- **R16 AI 文档与能力可运营化**：新增 `pages/ai-capability.html`（超管 / 销售运营）。文档回传清单区分已接管 / 未接管（只读 + 差异提示，不进入同步）与回传冲突（回传较新时保留本地未发布版本，人工核对）；填写模块按角色授权，运营只见授权模块，模块名称与填写说明不写入实际文档（提供实际文档预览核对）；SkillHub 清单分 可用 / 不可用 / 暂无法核实 三态，失效如实提示。沙盒验证为新会话无历史、只读真实数据、逐题人工判断留痕；未验证或验证未通过不能发布，内容再改作废旧验证。生产同步逐销售记录 送达 / 已加载 / 已生效，部分失败只展示失败项并可重试，未加载目标继续使用最近一次成功版本并标注；版本恢复生成恢复版本后仍需重新验证才能发布。运营配置 OpenClaw 页签的场景指引表单与演示沙盒已下线，改为只读摘要与 AI 能力运营入口。
- **R17 销售目标与进度**：新增 `pages/sales-goals.html`（销售本人看板 + 运营 / 超管三页签）。目标按层级（个人 / 全员）、指标（流水 / 毛利）、区间录入，目标值可设 0（与不设置区分），区间重叠允许并在列表提示；调整留痕（调整人、前后值、原因），历史不覆盖。流水 = Σ 结算金额（核减单列，口径待确认标注），毛利 = Σ（结算金额 − 配对成本），未配对成本与异常行进异常清单，重复数据按指纹去重；未归属业绩 = 全员达成 − Σ个人达成，目标差异只提示不调整。DataHub 收入成本同步分 正常 / 失败 / 从未接入 三态：失败保留最近一次成功结果并标注截止时间与原因（同时提醒运营），从未接入显示「暂无可用达成数据」，不提供模拟达成。目标录入与调整仅销售运营可写，超管只读（固化口径，界面已标注）。

待明确事项在原型中按以下假设演示并已在界面标注：行为记录「无可用内容」阈值（正文 < 10 字）、行为记录失败不发提醒（待 M05-2 §7.13）、R14 试跑空间上限 3 个、R17 目标维护仅销售运营可写（超管只读）、流水不扣核减、DataHub 数据为演示模拟（真实验收以联调为准）。

## R10 录音归位与客户信息更新（2026-09-21 改写）

原 `meeting-center` 是从旧前端迁入的「上传 → 解析 → 实体对齐 → 挂载」工作台，与 R10 定版口径相反。本轮按 R10 / M05-2 整体改写：

- **唯一来源改为三方同步**：移除上传录音表单与解析流水线状态，页面显式说明「本版不提供手动上传，也不做应用内录制；删除只在三方服务侧进行」。同步结果分 已同步 / 同步失败 两态，失败可见原因并可重新同步，单条失败不影响其余录音。归属销售标识缺失的录音不进入任何人的录音管理，只进运营「归属待处理」清单并经 R12 提醒运营与超管。
- **归位成为独立实体**：新增 `placements`，一条归位锚定一个客户空间和一条商机，记录归位人、时间、处理状态、对应变化与行为记录。录音自身不再带单值 `space` 字段；旧快照里的 `space` 会在加载时折算成一条归位记录，历史演示数据不丢。
- **归位校验顺序固定**：同步失败 → 空间冻结 → 非本人空间 → 无商机确权（仅客户级确权不可归位）→ 多商机未指定（系统不代选）→ 同一空间已存在（提示已存在，不重复建立）。单商机自动带出且允许修改。录音管理侧与客户空间「跟进 → 录音」侧发起的归位是同一种，两条路径等价。
- **一录多归位与逐条取消**：同一份录音可归位到多个空间，文件共用不切分，各条归位状态独立；从任一空间只看到与本空间相关的那条。取消只影响选中的那条，录音与其他归位不变；取消前已生成的变化与行为记录按原归位保留并标注，不回写到其他归位（留痕长期保留策略待 M05-2 §7.5）。
- **状态分三条线，不互相覆盖**：同步、转写（转写可用 / 等待转写，展示最近检查时间，不承诺固定时长）、归位处理（等待转写 / 更新完成·有变化 / 更新完成·无变化 / 更新未完成）各自展示；行为记录状态单列，客户信息写成而行为记录失败时两条结果分开呈现（种子 PL-105 / BR-510 演示）。
- **完成与异常反馈**：转写可用后自动进入客户信息更新，产出 R04 本次变化并同批触发 R15 行为记录。有变化或待确认时经 R12 提醒本空间销售且直达对应那次变化详情；无变化只更新状态不提醒；更新失败保留原内容、只提醒运营与超管，可按归位重试。

## R09 销售移动端基础与空间读写（2026-09-21 重建）

`mobile-ios-sales-assistant` 此前只是写死数据的「今日首页视觉稿」，四入口里只有「今日」可用。本轮按 R09 / M05-1 重建为可操作的移动端：

- **两端同源**：移动端直接加载网页端的 `js/data.js` 与 `js/features/store.js`，业务状态共用 `localStorage` 键 `sc-v02-feature-pages-v1`，权限与内容全部调用桌面同一套 `F.*` 函数，不做分端存储——手机上写的跟进在网页端刷新即可见（`tests/mobile.cjs` 对这条做了跨页面断言）。只有离线开关、离线缓存过的空间和未提交草稿三项设备本地状态单独存放在 `sc-v02-mobile-local-v1`。
- **保留导入时的视觉资产**：「今日」顶部欢迎区（打字机文案、会眨眼的助手图标、「进入聊天助手」入口）与顶栏日期标题逐字保留；欢迎区动效随路由重画补挂，仍按会话只播一次，滚出可视区域后暂停动画。
- **四入口与本人助手**：底栏固定今日 / 客户 / 相关 / 我的，不再出现「下一版开放」。四个主入口都能调起同一个本人助手，但入口按场景分工、不叠在同一屏：「今日」用欢迎区自带的「进入聊天助手」按钮，客户 / 相关 / 我的用右下角常驻悬浮入口；进入客户空间后悬浮入口收起，该场景由概览内的空间助手承接，两类助手不混用。「相关」本版只承载录音管理入口（含 R10 归位），其余留白。
- **今日**：本周经营与网页端销售目标看板同一份取数，DataHub 不可用时只说明来源状态、不提供模拟达成；「今天该跟」消费与网页端同一份当日快照（不在移动端另算），含状态种类、一句话、下一步、判断依据与星标 / 暂不跟进入口；收件箱未读优先带计数，每条只有一个动作，不装全员广播类内容，客户更新类条目直达对应那次变化。
- **空间详情**：顶部客户名、客户池与状态角标（冻结 / 更新中 / 更新失败 / 离线）跨 Tab 常驻；五个 Tab 常驻、默认落地概览且不记忆；概览常显区为一句话判断、快捷问答、当前卡点、关键人与联系人、最近动静，其余板块折叠且每次进入重新收起；点击联系人入口深链跳客户 Tab 并高亮目标区块。跟进 Tab 分跟进记录 / 行为记录 / 方案往来 / 录音四段，录音按归位逐条展示状态不汇总。资料 Tab 只读，不提供上传或重试。
- **写入**：跟进记录必须关联商机（仅客户级确权的空间可读不可写），周复盘填写进展 / 下一步 / 阻塞；提交后进入 R04 异步更新并同批产出行为记录，重复点击只生成一条。冻结空间不呈现任何写入入口并标注冻结时刻。
- **离线与并发**：最近打开过的空间离线可只读并标注最后更新时间，未缓存的空间如实提示需要联网；离线写入只存本机草稿、不自动提交，联网后由本人在空间内或「我的 → 待确认草稿」核对确认。提交携带基线版本，另一端已先提交时按先提交为准给冲突提示、保留输入并把草稿标为冲突待处理。
- **方案接收**：收件箱条目进空间后首次打开方案即标记已读并回传方案人员，单轮回复后本轮结束；冻结或离线时方案往来只读。
- **同步改动**：为满足「两端同一份」，网页端跟进表单同步加上「关联商机」必选字段，并新增周复盘写入与时间线展示（`F.addWeeklyReview`、`F.weeklyReviewsOf`），两端共用 `F.writeBaseline` / `F.assertNoConflict` 做并发判定。

本轮未覆盖：本人助手「暂不可用」态需要 R11 先定义助手可用性模型，当前悬浮入口恒为可用；`?as=` 仅用于切换演示销售身份，不代表真实登录链路。

## 评审路线

1. 以销售打开录音管理，核对未归位 / 等待转写 / 同步失败三种状态；把「线路试点技术交流」归位到星辰科技（单商机自动带出），再试着归位到云桥数字（多商机不指定应被阻止）、海川保险（仅客户级确权应被阻止）和已冻结的和光医疗；打开「跨客户联合沟通」查看一录两归位的独立结果，取消其中一条后确认另一条不受影响；打开「采购预算及交付确认」点「演示转写完成」，确认对应归位自动进入客户信息更新。
2. 以方案人员打开方案人员工作台，展开星辰科技并进入方案推送；选择通信线路池 / 智能短信池的正常空间推送，查看逐空间结果；切换销售进入消息中心，再进入空间查看并回复；回方案人员查看反馈看板中的阅读、回复与催办状态。
3. 超管进入运营配置 → 承接池配置，调整闫丽梅承接池；用同一浏览器的方案人员页面验证范围同步。
4. 查看已冻结的和光医疗空间，确认没有跟进写入和方案回复入口。
5. 运营查看经营洞察、数据洞察和方案推送跟进；筛选后打开详情或导出 CSV。
6. 以方案人员进入星辰科技空间 → 资料入口，查看六层内容范围；上传时同时勾选正常文件、PDF、空正文、超大文件、重复文件、同名不同内容文件和预期失败文件，核对逐份反馈，再对失败项单份重试。
7. 以销售进入同一空间的概览入口，核对十个板块、依据入口和「本次变化」；提交一条跟进后确认出现新增与前后对比；再打开和光医疗的冻结空间，确认无新问答入口但历史可读。
8. 以销售打开客户入口，核对「同客户在跟名单」只给销售与确权类型；再以超管在运营配置 → 承接池配置调整闫丽梅的池，回到列表核对变更提示与最后更新时间。
9. 以销售运营打开客户归属视图，依次查看星辰科技（同客户两位销售）、云桥数字（待对应人员与未分配商机）、海川保险（内容失败），确认当前与历史分栏且历史区域无任何操作入口。
10. 以销售打开今日该跟，核对名单快照口径、状态种类、依据抽屉与截断说明；对星辰科技做星标与暂不跟进（不填原因应被阻止），确认当天名单不变且标记记录可查；再以销售运营进入经营洞察编排，编辑排序提示词草稿、按空间试跑对照并上线，确认次日生效与发布留痕。
11. 以销售打开晚间日报，核对今日总览、客户块七栏与「未能生成的客户」；切换方案人员确认只看承接客户块合集且无总览；再以销售运营在运营配置 → 晚间日报查看运行记录与失败客户详情。
12. 以超管打开 AI 能力运营，依次核对未接管文档只读、回传冲突标注、运营分权填写、skill 三态、沙盒验证逐题判断与发布门禁，以及逐销售发布结果中的失败重试与「未加载新版 · 继续使用旧版」标注。
13. 以销售运营打开销售目标与进度，录入一条个人目标并调整留痕；核对逐人进度、目标差异与未归属业绩；在数据状态分面模拟取数失败，确认看板保留最近成功数据并标注原因，再重置为未接入确认不显示模拟达成。
14. 打开 `mobile-ios-sales-assistant/pages/mobile-ios.html`，依次切四个入口确认本人助手悬浮入口常驻；在客户入口搜索「远山」，进入空间核对五个 Tab、折叠区默认收起、点击联系人入口深链高亮；在跟进 Tab 写一条跟进（不选商机应被阻止）并提交，回到网页端同一客户空间刷新，确认读到同一条。
15. 在移动端「我的」打开「模拟离线」，回到刚才的空间确认标注离线内容、写入只存草稿；再打开一个没进过的空间确认提示需要联网；关掉离线后在「我的 → 待确认草稿」核对并提交，观察冲突提示与草稿保留。

## 本轮边界

- 演示数据均为样例；页面不调用后端、CRM、消息渠道和真实模型。
- 录音不提供上传入口：列表为三方同步的演示数据，转写完成、重新同步与更新重试采用显式演示按钮，不保存音频二进制、不做真实转写。
- 移动端为浏览器内的 iOS 视觉原型，不含企业内部分发、安装包、真实推送授权与设备能力；离线通过「我的」里的演示开关模拟，不依赖真实网络状态。
- 方案推送已实现正文、单个演示附件和外部链接的状态闭环；附件不上传真实二进制，外部链接仅作为原型中的链接字段展示。
- 模型配置仅检查格式；OpenClaw 沙盒、渠道绑定及服务健康为本地快照。未实现真实连通性检查、Agent 编排或生产发布。
- 产品知识保留核心资料与常见问题编辑；富文本、图片、案例和多版本管理未迁入。

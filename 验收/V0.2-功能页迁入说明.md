## 跟进工作台与客户空间的关系（2026-09-20 修正）

此前 `followup-workbench` 既占据销售的一级菜单位，又实际承载客户空间详情，把两件事混成了一个页面。本轮拆开：

- **跟进工作台**是销售侧处理各类信息的独立工作台，本版尚未实现。销售菜单保留该条目但**封存**：渲染为不可点击的 `<span>`，带 `aria-disabled="true"` 和「本版未开放」标记，不进入 Tab 焦点顺序，角色切换也不会落到它。
- **`followup-workbench` 路径不禁止访问**，直接输入 URL 仍可打开，并按**次级页面**渲染：页面标题为「客户空间」，操作条显示「返回客户空间列表」，左侧高亮父级「客户跟进空间」而不是自身。带 `solution` 参数进入时返回目标仍是该客户空间的方案页签。
- 销售登录后的落地页由「跟进工作台」改为「客户跟进空间」；进入具体客户仍从列表点击，链接不变。

真正的跟进工作台实现后，解除该菜单位封存即可，客户空间路径与其父子关系不受影响。

## 登录与角色入口

- 根入口 `index.html` 为 V0.2 登录页；17 个功能页的逐页评审入口迁至 `prototype.html`。
- 登录页提供超级管理员、销售运营、销售和解决方案人员四个演示身份，选择后自动填入本地凭据。
- 登录成功后分别进入「运营配置」、「经营洞察」、「客户跟进空间」和「方案人员工作台」，并带上与身份匹配的 `role` 和 `as` 参数。
- 会话只保存最小演示身份，不保存密码；退出登录会清理会话并返回根登录页。
- 该链路是静态原型交互，不是真实身份鉴权。为便于需求评审，带角色参数的功能页直达链接仍然可用。

## 数据及权限

- 使用独立本地存储，不依赖旧批次的审批与组织数据。
- 销售仅见本人空间；解决方案人员仅见显式承接池；运营 / 超管可全量查看空间。
- 冻结空间保留只读；客户级确权样例可进入但商机为空。
- 客户池和销售的归属变化来自 CRM；新功能页没有本地创建归属池或更换空间归属的入口。
- 承接池调整支持逐项多选，不提供“全部”选项。提交时重读范围，已打开页面不能继续对失去权限的方案操作。
- 多空间推送为每个空间创建独立记录，正文、附件、外部链接、已读时间与回复时间互不串联。销售打开详情后已读，一次回复闭环；方案人员打开后标记回复已读。
- 只有原推送人能撤回未读方案。撤回后销售侧记录与提醒失效。
- 撤回记录不从方案人员的反馈看板消失，并在详情中保留撤回时间与事件记录；承接池变化导致的旧空间非撤回方案仍按当前可见范围隐藏。
- 催办演示采用 24 小时间隔，只生成本地提醒；看板记录催办次数和最近时间，不是生产限流口径的定版。
- 录音挂载与跟进记录原子写入，重复挂载被阻止。

## 客户跟进空间列表优化与分页（2026-09-22）

`pages/customer-spaces.html`（R02 入口 / R05 权限统一入口）首屏被三段头部占满：权限结果 192px + 指标卡 248px + 筛选区 113px，表格要到 y=657 才出现，1440×900 下一屏只看得到 3 行。本次按「先给列表」重排：

- **权限结果压成两行**：身份徽章与判定结论并入面板头（`可见 N 个空间，其中 M 个已冻结只读`），可读 / 可写合并为一行两列（`可读 … 可写 …`），SOL 的承接客户池追加在同一行。信息一项未删，高度 192px → **127px**。
- **指标卡改为可点筛选**：六张卡一行排布（桌面 6 列）；`进行中 / 已冻结 / 内容更新中 / 内容失败` 四张可点，点击即把列表收敛到该状态并在卡上显示按下态（`is-active` + `aria-pressed`），再次点击取消；`客户 / 跟进空间` 为规模口径，保持纯展示。卡面文案同时标明交互（`· 点击筛选` / `· 再次点击取消`）。
- **新增「内容就绪度」筛选器**：全部 / 内容已就绪 / 内容更新中 / 内容更新失败，与指标卡共用同一份过滤条件，筛选标签同步输出「内容：内容更新失败」，避免卡片数字与列表对不上。
- **窄屏筛选区默认收起**：`≤760px` 时筛选控件收进列表头的「筛选条件」开关（带生效条件计数），有筛选条件时自动展开；点击指标卡后把列表滚进视野，避免「点了卡片却在屏外看不到结果」。
- **表格分页**：新增分页条（`第 x / y 页 · 共 N 个空间` + 上一页 / 下一页），每页 5 条（演示数据 9 个空间 → 2 页，分页行为可验收）；筛选条件变化时回到第一页，页码越界自动收敛；列表头计数同步显示 `N 个空间 · 第 x / y 页`。分页条为通用组件（`.fp-pagination`），与人员管理列表分页保持同一交互语言，窄屏按钮撑满并保持 44px 触控高度。

实测（1440×900，ADM）：权限结果 192 → 127px、指标卡 248 → 128px（6 列一行）、表格出现位置 y=657 → **y=471**，一屏可见行数 3 → **5**；页面总高 1325 → 924px。窄屏 420px：表格出现位置 y=1137 → 778px（筛选区默认收起）。

改动文件：`原型/js/features/customers.js`（权限面板结构、指标卡与筛选器联动、分页）、`原型/css/features.css`（`.fp-permission-*` / `.fp-space-metrics` / `.fp-pagination` / 窄屏筛选开关）、`原型/tests/features.cjs`。

## R08 反馈看板操作列优化（2026-09-22）

`pages/solution-feedback.html`（R08 反馈看板）的操作列同时塞了三样性质不同的东西：两个 `.btn` 按钮（查看详情 / 催办）、一个没有类名的裸 `<a>`（回到空间）、以及一句状态说明（`已回复，无需催办` / `撤回记录` / `空间冻结`）。列头写着「操作」，内容却一半是动作、一半是状态；单元格靠 `width:1%` + `nowrap` 占住 270px，把数据列挤到折行。本次按 R01「操作列去按钮化」的同一套语言收敛：

- **操作列只放动作，且统一为文字动作**：`查看详情`（主操作，`is-main`）、`回到空间`（真实链接，承载 R08 4.3「点击可返回原空间」）、`催办`（仅未撤回、未回复、空间正常时出现）放进独立布局容器 `.fp-row-actions`，不再依赖单元格 `display` 的偶然行为。操作列不再渲染任何 `.btn`，控件高度由「34px 按钮 + 16px 裸链接」的混排统一为 24px 一行（窄屏 44px 触控行高）。

## R10 录音归位与客户信息更新（2026-09-21 改写）

原 `meeting-center` 是从旧前端迁入的「上传 → 解析 → 实体对齐 → 挂载」工作台，与 R10 定版口径相反。本轮按 R10 / M05-2 整体改写：

- **唯一来源改为三方同步**：移除上传录音表单与解析流水线状态，页面显式说明「本版不提供手动上传，也不做应用内录制；删除只在三方服务侧进行」。同步结果分 已同步 / 同步失败 两态，失败可见原因并可重新同步，单条失败不影响其余录音。归属销售标识缺失的录音不进入任何人的录音管理，只进运营「归属待处理」清单并经 R12 提醒运营与超管。
- **归位成为独立实体**：新增 `placements`，一条归位锚定一个客户空间和一条商机，记录归位人、时间、处理状态、对应变化与行为记录。录音自身不再带单值 `space` 字段；旧快照里的 `space` 会在加载时折算成一条归位记录，历史演示数据不丢。
- **归位校验顺序固定**：同步失败 → 空间冻结 → 非本人空间 → 无商机确权（仅客户级确权不可归位）→ 多商机未指定（系统不代选）→ 同一空间已存在（提示已存在，不重复建立）。单商机自动带出且允许修改。录音管理侧与客户空间「跟进 → 录音」侧发起的归位是同一种，两条路径等价。
- **一录多归位与逐条取消**：同一份录音可归位到多个空间，文件共用不切分，各条归位状态独立；从任一空间只看到与本空间相关的那条。取消只影响选中的那条，录音与其他归位不变；取消前已生成的变化与行为记录按原归位保留并标注，不回写到其他归位（留痕长期保留策略待 M05-2 §7.5）。
- **状态分几条线，不互相覆盖，且不设转写阶段（2026-09-21 二次校正）**：转写由得到笔记完成，同步成功即带智能总结与原文，本系统不发起、不执行、不等待、不重试转写（M05-2 §边界、0921 口径），因此页面不出现「等待转写 / 转写中 / 转写失败 / 最近检查」等任何转写状态。可见状态线只有：同步（已同步 / 同步失败）、归位处理（客户信息更新中 / 更新完成·有变化 / 更新完成·无变化 / 更新未完成 / 已取消归位）与行为记录（单列）。客户信息写成而行为记录失败时两条结果分开呈现（种子 PL-105 / BR-510 演示）。
- **完成与异常反馈**：归位后立即使用三方已同步的转写文本进入客户信息更新（种子 PL-102 停在「客户信息更新中」演示未落地状态），产出 R04 本次变化并同批触发 R15 行为记录。有变化或待确认时经 R12 提醒本空间销售且直达对应那次变化详情；无变化只更新状态不提醒；更新失败保留原内容、只提醒运营与超管，可按归位重试。原型不做真实异步处理，抽屉里提供显式的「演示：完成本次更新」入口把「更新中」推进到实际结果。
- **来源内容异常**：同步失败、或同步成功却没带回转写文本，都按来源内容异常处理（`F.recordingSourceIssue`）——录音仍可见，标出来源原因、不可归位、不进入客户信息更新，也不伪装成「等待转写」；重新同步成功后取回三方已有的总结与原文，回到可归位状态。录音内容抽屉的两栏在异常时如实说明缺位，不用摘要冒充原文。
- **录音内容两栏**：录音管理详情、客户空间「跟进 → 录音」的查看原文、更新历史节点、行为记录依据与「今日该跟」依据抽屉，都复用同一份 `F.recordingContent`，展示「智能总结 / 录音原文」两栏（默认智能总结），并标明内容由得到笔记（三方录音服务）同步提供、三方已完成转写。
- **空间侧归位入口（2026-09-21 补充）**：客户空间「跟进 → 录音」子页补齐 M05-2 §4.2 归位路径二——列表右上方一个安静的小按钮「归位录音」（`.rec-place`，28px 高、浅灰底 + 灰字，全站不用蓝底白字；同一处不再并列其他入口）。点开走全站同一套 4/5 屏底部抽屉，**只列未处理的录音**（尚无有效归位，与录音管理「未处理」同一口径，抽屉副标题写明「N 条未处理」），已归位的到录音管理侧再挂；同步失败的如实标「不可归位」并给出原因、且不给归位按钮。抽屉里不放商机选择：每行右侧两个小按钮——「查看详情」用同一套 4/5 抽屉展示智能总结 / 录音原文（头部左上角是返回按钮，点它回到下面的挑录音抽屉，不关整层），「归位到本空间」在仅一条商机时自动带出直接归位、多条时先开「选择商机」抽屉逐条列出（系统不代选）。校验顺序仍由 `F.assertPlaceable` 兜底。冻结空间与仅客户级确权的空间不出现该按钮（不留空入口条），后者同时说明「没有商机，归位必须锚定商机」。

### 空间助手对话逻辑对齐（2026-09-21 补充）

网页端空间助手从「内容列表 + 单行提问」改为与移动端空间助手同一套对话逻辑：

- **条目式对话**：一条问答＝两条条目（左侧等宽时间栏 + 用户右对齐批注 + 助手答案），历史按时间正序渲染，最新一条在最下方并自动滚到底。数据仍来自共享的 `state.spaceQA`，两端看到同一份历史。
- **依据改为脚注**：答案不再挂溯源胶囊，改为可点的 〔n〕（`data-qa-cite`，失效来源 `data-qa-cite-broken` 划线且只说明失效）；点击复用同一套 `openSource`，录音依据会打开录音内容两栏。
- **作答过程可见**：发送后先落骨架屏（`data-qa-skel`），再按 30ms／5 字流式出字并带光标；发送键在作答中切换为停止（`data-qa-send` 的 `data-state` 在 `send`／`stop` 间切换），停止会撤掉未完成的作答、不写入历史，已出字时保留已生成部分并在口径行标「已停止生成」。`window.FN_FAST` 时跳过等待与流式直接出结果（回归用，与移动端同一开关）。
- **空会话引导区**：没有历史且空间未冻结时展示「只围绕这个空间作答」+ 口径说明 + 四个预设问题（`data-qa-presets`），开口后引导区让位。
- **消息操作**：答案可复制；重新生成只留给最后一条答案，走 `F.discardSpaceQA` 先丢弃旧记录再重问，历史里不留重复答案。鼠标悬停、键盘聚焦或右键（`contextmenu`）唤出，不占常驻版面。
- **输入区钉底**：抽屉内容区自己滚、输入区固定在下沿（`.fp-drawer--chat`），自增高输入框（上限 132px），Enter 发送、Shift+Enter 换行、输入法组合态不误发。冻结空间整体不出现输入区与预设问题。

## 本轮边界

- 演示数据均为样例；页面不调用后端、CRM、消息渠道和真实模型。
- 录音不提供上传入口：列表为三方同步的演示数据，重新同步与更新推进采用显式演示按钮；不保存音频二进制、不做真实转写（转写由得到笔记完成，原型只消费同步结果）。
- 移动端为浏览器内的 iOS 视觉原型，不含企业内部分发、安装包、真实推送授权与设备能力；离线通过「我的」里的演示开关模拟，不依赖真实网络状态。
- 方案推送已实现正文、单个演示附件和外部链接的状态闭环；附件不上传真实二进制，外部链接仅作为原型中的链接字段展示。
- 模型配置仅检查格式；OpenClaw 沙盒、渠道绑定及服务健康为本地快照。未实现真实连通性检查、Agent 编排或生产发布。
- 产品知识保留核心资料与常见问题编辑；富文本、图片、案例和多版本管理未迁入。
- 旧版审批、分组、客保及池创建页已从本目录移除，避免据此误判 V0.2 有效需求。

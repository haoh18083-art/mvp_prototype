# CRM数据管理：UI 审核与改版说明

日期：2026-09-09  
页面：P-ADM-23，`pages/reconcile.html`  
入口：http://127.0.0.1:8777/pages/reconcile.html?role=ADM&as=U-1001

## 1. 使用场景与设计目标

这是超管在桌面端查看来源读取结果、发现待办、进入责任页面的工作总览。它位于已有后台导航内，日常任务是快速判断“同步是否正常、有哪些数据需要核对、从哪里处理”。同步操作可能影响共享演示数据，因此本次使用既有同步动作与身份机制，展示数字均取自已有共享数据，不添加模拟趋势、成功率或虚构告警。

设计目标：用区域位置、色块和字号建立明确的阅读顺序，同时区分来源读取、人工核对与下游空间状态。

## 2. 原界面问题与对应修改

| 问题 | 对用户的影响 | 已实现的调整 |
| --- | --- | --- |
| 大量白底、细边框，七个入口拥有相同的尺寸和视觉权重 | 看不出主要任务，状态与操作混杂 | 顶部深蓝接入区、中部琥珀色核对区、底部运行记录与辅助状态区 |
| 同步成功与空间、Agent 失败混在“核对工作区” | 容易把空间建立失败理解成 CRM 同步失败 | 空间与 Agent 单独分区，并说明其状态独立于 CRM 同步结果 |
| “当前实例”与正式客户、商机数并排 | 统计对象跨业务阶段，不易理解 | 客户与商机保留在顶部；当前实例移到空间与 Agent 区 |
| 同步成功在接入卡、指标栏和入口卡重复出现 | 占用面积而没有增加判断依据 | 接入卡集中展示最近同步结果及最近成功时间；运行记录保留每次真实状态 |
| 数字与入口动作距离远，数字含义弱 | 需要来回扫视才能判断待办规模 | 三类核对卡展示大数字、计数单位和明确的处理动作，整卡可点击 |
| 最近同步记录被七张入口卡挤到下方 | 核查运行结果需要额外滚动 | 三类核对入口横排；最近同步与辅助状态并排上移 |
| 最近三条记录仍带无效的上一页、下一页按钮 | 占空间并暗示存在更多可翻页内容 | 精简为最近三次运行表，提供“全部记录”入口 |
| 原状态判断没有完整处理失败及无记录 | 失败可能显示为绿色；无记录时直接读取首项可能报错 | 统一成功、部分成功、失败、同步中、无记录五种展示 |

## 3. 区域与视觉规范

```text
页面说明                                      刷新状态 / 手动同步
┌────────────────────────┬─────────────┬─────────────┐
│ CRM 接入状态 · 深蓝底    │ 正式客户    │ 真实商机    │
│ 最近成功时间 / 接入入口  │ 数量与口径  │ 数量与口径  │
└────────────────────────┴─────────────┴─────────────┘
┌ 来源数据核对 · 琥珀色底 ────────────────────────────┐
│ 数据异常              来源差异          待合并客户  │
│ 数量 / 核对数据       数量 / 查看差异   数量 / 核对客户│
└───────────────────────────────────────────────────┘
┌ 最近同步 ─────────────────────┬ 空间与 Agent ──────┐
│ 最近三次运行 / 全部记录        │ 当前实例 / 全部实例│
│ 触发方式、时间、结果、本地保留 │ 三类异常快捷入口   │
└───────────────────────────────┴───────────────────┘
```

- 沿用项目品牌蓝，深蓝背景为 `#1b3d5c`；核对区域采用 `#faf7f0` 暖底；辅助状态区使用浅蓝灰。
- 成功为绿色、部分成功和待处理为琥珀色、失败为红色、同步中为蓝色、无记录为灰色；同时展示文字或状态点，避免只靠颜色判断。
- 页面标题 22px，区域标题 15px，入口标题 14px；核心统计数字 40px，待办数字 32px。正文和说明明确分级。
- 保留现有中文字体、图标体系和导航；内容圆角以 6–8px 为主，区块间距 16–20px。悬停仅调整颜色与边框。
- 操作使用 button，跳转使用 a；链接提供键盘焦点描边，同步动画支持减少动效设置。

本次组件层级为页面 → 区域 → 内容项：接入概况、核对事项、运行记录、下游状态四组。空间失败仍保留可达入口，前一轮讨论的“迁至跟进准入终审”属于另外的菜单职责调整，本次未实施该流程迁移。

## 4. 数据来源与交互

| 展示项 | 取值依据 |
| --- | --- |
| 最近同步结果 | 当前同步锁及 `runs[0].state` |
| 最近成功时间 | `lastSuccess`，无值时显示暂无成功记录 |
| 正式客户 | `customers` 中非 merged 项 |
| 真实商机 | `opps.length`，沿用原页口径 |
| 三类待处理 | issues、diffs、merges 中 state 为“待处理”的数量 |
| 总待处理 | 上述三类事项数量相加，单位为“项”，不是去重客户数 |
| 当前实例 | agents 中 current 为 true 的数量 |
| 空间失败 | spaces 中 status 为 failed 的数量 |
| Agent 绑定／读取失败 | 当前实例中 bindfail／readfail 的数量 |
| 最近同步表 | runs 的前 3 项，展示 id、trigger、start、state、kept |

手动同步继续调用现有 `B.startSync()`，同步中禁用按钮；刷新状态重新读取共享数据。相关事项处理后返回总览或跨页数据变更时，继续使用现有 `B.render()` 与 storage 监听更新。全部跳转使用 `B.href()`／`B.link()` 保留角色与人员身份。

## 5. 状态覆盖

| 情况 | 展示 |
| --- | --- |
| 成功 | 绿色状态标签，显示真实最近成功时间 |
| 部分成功 | 琥珀色标签，各运行记录保持自身结果 |
| 失败 | 红色标签，不将上次成功时间当作本轮成功 |
| 同步中 | 蓝色标签，主按钮禁用并显示“正在同步” |
| 无运行记录 | 显示“暂无同步记录”，保留发起同步及接入入口 |
| 待处理数为 0 | 显示 0／暂无待办，降低卡片的告警强调 |
| 无权限 | 沿用公共页面壳的无权访问逻辑 |

## 6. 响应式规则

1200px 以下压缩区块间距；1050px 以下接入卡独占一行、两项统计并排，底部改为单列；760px 以下操作按钮换行、三类核对卡纵排，记录表只在自身容器内横向滚动。所有区块使用可收缩网格，避免长标识撑开页面。

## 3. 目录结构

```text
原型/
├── index.html              原型导航
├── README.md               本文件
├── css/
│   ├── tokens.css          设计变量（色板 / 字号 / 间距 / 圆角 / 阴影 / 结构尺寸）
│   ├── base.css            重置、排版、工具类
│   ├── layout.css          主框架布局（侧栏 / 顶栏 / 内容区 / 两栏详情）
│   ├── components.css      通用控件 + C-01 ～ C-12 规范组件
│   └── pages.css           页面独有排布（登录、导航、人员详情、审计、组件总览）
├── js/
│   ├── data.js             演示数据（人员、分组、字典、审计事件、六域清单）
│   ├── menu.js             四角色默认菜单配置 + 空态占位页文案
│   ├── components.js       组件渲染库（图标、状态标签、弹窗、Toast、分页、全选联动）
│   ├── layout.js           主框架注入 + SC.page() 页面入口
│   └── pages/              每页面一个脚本，与 pages/*.html 一一对应
└── pages/                  每页面一个 HTML
```

**页面拆分方式**：每个页面是独立的 `.html` 文件（真实跳转，不是单页应用），但**主框架不重复写在每个 HTML 里**——`pages/*.html` 只声明 `<div id="sc-app">` 与脚本引用，左侧菜单区和顶部信息区由 `js/layout.js` 统一注入。这样共用框架的页面菜单保持一致，改一处即全站生效。

批 3 已按[业务闭环页面详设](../页面设计/批3-业务闭环页面详设.md)实现 34 页已确认范围，详见第 11 节。联系人录入、正式跟进、录音文件处理、方案交付、合同与 Agent 分析等后续能力仍不模拟提交成功。

新增页面的三步：

1. 复制任一 `pages/*.html`，改最后一行的脚本路径；
2. 新建 `js/pages/<name>.js`，调用 `SC.page({role, menu, pid, title, desc, crumb}, function(body, actions){…})`；
3. 在 `index.html` 增加一张导航卡片。

### 10.1 组件与页面边界

```text
css/batch2.css             批 2 共用布局、表格、表单、状态及窄窗口规则
css/pages/<page>.css       16 页各自的排布差异
js/batch2/store.js         虚构数据、持久化、关系校验、操作记录
js/batch2/ui.js            复用 SC 主框架/状态；增强表格、表单、弹窗、页签
js/batch2/pool-actions.js   多页面复用的池创建、转入、批量指定与人员分配
js/batch2/product-actions.js 产品信息与激活操作
js/batch2/recon-actions.js  同步演示与异常验证
js/pages/<page>.js         16 页独立的视图和页面事件
pages/<page>.html          独立入口，只引用所需公共文件与页面脚本
js/xlsx-read.js            零依赖 .xlsx/.csv 读取器（内置解压 + DOMParser）
js/people-import-validate.js 批量导入合法性校验（M01 §4.2 判定规则，纯逻辑）
js/vendor/                 本地 Lucide 图标与许可证
assets/                    批量导入真实模板与演示样例（.xlsx）
tools/gen-import-template.py 生成 assets/ 内 .xlsx 的脚本（需 openpyxl，仅生成时用）
tests/                     页面检查和业务流程测试
```

批 1 的组件与主框架未重写。批 2、批 3 共用 `localStorage` 的 `sc-prototype-batch2-v1`；查询条件/产品草稿使用 `sessionStorage` 的 `b2-` 前缀项。批 3 扩展同一份数据，不复制已有客户、产品与客户池。导航页重置操作会清除批 2/3 的共享虚构数据及已联动的账号启停状态，不影响真实业务；浏览器禁用存储时会显示保存限制。

### 10.2 已实现与明确未接入

- 查看影响、取消确认不产生业务变更；批量操作分别返回成功、失败、未处理和未变化。
- 产品保存不等于激活；取消激活保留商机归属、客户池与历史；既有计费纠错不开放。
- 来源候选不计入正式客户/商机；空间冲突阻止合并；主体确认不自动批准来源商机冲突。
- 客户级归属销售分组仅超管查看，支持多值、“待分组”和“无”；其他角色不新增该字段。
- 绑定与读取分别重试，读取失败仍保留绑定；历史已停止实例无重启入口；上下文错误不通过伪造关联解决。
- 批 3 已接入客保/准入的本地审批交互、空间与授权历史查看，并替换相应跨批占位跳转。联系人新增/编辑、产品历史纠错、方案任务重派及真实外部业务接口仍未接入，不模拟这些能力提交成功。
- “手动同步”与延迟恢复仅用于本地状态演示，没有五分钟真实后台轮询、外部接口、真实鉴权或生产级并发事务。角色切换是原型评审工具，不是生产权限系统。
- 批 2 操作记录在相关页面可查看；尚未把批 1 的静态审计样例改成完整的跨批审计系统。

### 11.2 可以验证的闭环

- 首批整单：全部产品一起校验、一起生成；取消不生效，产品失效不部分创建，重复确认不会再建一批对象。
- 后续商机：本组/跨组审批权按当前关系重判，普通条目分别处理；恢复的原结束结果及生效前后关系保存为可查快照。
- 公海：候选与正式公海分开；领取首条生效后退出公海，剩余已受理条目转加入认领并重判受理权。
- 普通准入：销售与方案人员对同组合去重提报；通过和驳回分支独立校验，产品条件不满足仍可有权驳回；空间结果不回退准入。
- 空间与权限：按销售、客户、客户池定位；方案侧不展示混合内容或实例运行状态；空置手动归档、回池解档保留空间并新建实例。
- 交接：同一原销售客户组全部去向明确才生效；保留原池与原经营结果；完整迁移保持空间/实例，拆分则只读原空间并按原空间授予历史权。
- Q-B3-01 A：目标已有普通准入待办继续原终审，交接页不另批、不接管或自动关闭。原空间只读归档后，后来准入通过只建立/沿用目标空间，不倒推迁移。
- 跨批：批 2 的商机/组合/空间/来源冲突入口进入实际批 3 页面；批 1 的查看交接明细不执行停用，账号启停不改变归属，并持久化到共享数据。

### 11.3 演示样例与边界

首次进入批 3 会在共享数据中追加明确的虚构申请、交接和历史记录样例，不覆盖批 2 已维护的主数据。默认可查看：

| 样例 | 位置 |
| --- | --- |
| 两个产品的首批整单 | [REQ-3901](pages/verdict.html?request=REQ-3901) |
| 产品失效而不能通过的首批 | [REQ-3908](pages/verdict.html?request=REQ-3908) |
| 未成交恢复与原关系快照 | [REQ-3903](pages/manager-approvals.html?role=MGR&as=U-1002&request=REQ-3903) |

这仍是前端原型：所有审批、同步、空间和实例都是本地状态模拟，没有生产鉴权、外部通知、真实 Agent 或跨进程事务保证。样例记录只用于验证承载与权限，不代表已接入录音文件、方案/合同提交或完整跟进业务。来源候选未定位到可确认的真实商机关联时只提供核对去向，不虚构“批准并行商机”。批 1 的完整审计台仍主要是静态样例，批 3 的真实本地申请/决定/分配/交接结果可在各详情与审批记录中查询，不宣称生产审计系统已经交付。

## M02 数据联动与验收（2026-09-09）

销售分组、人员角色与主管当前任职统一保存在原型已有的 `sc-prototype-batch2-v1` 本地数据中。创建、改名、首次分配、主管继任及转岗解除成员关系均真实保存；刷新、跨页查看与主管待办使用同一份关系。原有数据自动补齐组织关系，不要求清空已完成的演示操作。

- `js/organisation.js`：分组关系、角色业务检查、并发确认、统计与审计快照。
- `js/m02-ui.js`：两个分组页面共用的成员选择、分配和主管继任弹窗。
- `js/m02-bootstrap.js`：M02 页面使用现有批 3 业务演示数据，避免首次打开不同页面造成统计不一致。
- 主框架、客户页签与后续 PRD 空态页保持当前人员；四角色登录进入对应默认首页。
- 角色变更依照 M01：先停用、清理业务关系、改角色，再手动启用。主管继任不自动启停账号，也不重建审批单。

本次沿用原型既有的“一名主管管理一个分组”约束。页面上的角色／人员选择器仍是原型演示工具。

业务数据使用浏览器 `localStorage`，演示登录身份和筛选条件使用 `sessionStorage`。同一浏览器、同一来源下的页面可共享；不同浏览器或电脑不互通，不连接数据库、CRM 或真实后端。原型导航页的重置会一并清除本轮分组和角色演示变更。
